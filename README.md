
# ExplainMyBody

인바디 이미지에서 신체 정보를 추출해서 상태를 분석하고, AI 기반으로 주간 운동 및 식단 계획을 만들어주는 도구

> **베타 버전**: 알파 버전에서 추가적으로 LangGraph를 활용한 피드백 루프 및 실시간 스트리밍이 적용되었음. 추가적인 기능 개선 준비 중.


## 주요 기능 (Beta 기준)

### 🔹 핵심기능

- **InBody OCR 파이프라인**
  - 이미지 업로드 및 추출: 인바디 이미지에서 **39개 주요 신체 지표**(체성분, 골격근, 지방 등) 추출 및 전산화.
  - 데이터 검증: OCR 추출 결과를 사용자가 직접 확인하고 수정하여 데이터의 정확성 확보.
  - **지능형 예외 처리**: 인바디와 관련 없는 이미지나 판독이 불가능한 사진 업로드 시 명확한 가이드 제공.

- **AI 분석 & 주간 계획 챗봇**
  - **기록 비교 분석**: 단순 분석을 넘어 **과거 인바디 기록과 현재 상태를 비교**하여 신체 변화 추이 요약.
  - 맞춤형 주간 계획 생성: 사용자의 목표, 운동 선호도, 건강 특이사항을 반영한 최적의 운동·식단 계획 제안.
  - **대화형 계획 수정 (Human Feedback)**: 생성된 계획에 대해 사용자가 챗봇과 대화하며 실시간으로 내용을 조정 및 재작성.
  - **멀티턴 스트리밍 응답**: 이전 대화 맥락을 기억하는 멀티턴 대화와 대기 시간 없는 **실시간 응답(Streaming)** 지원.

### 🔹 부가기능

- **사용자 체형 분석**
  - 체형 분석: 사용자의 인바디 데이터를 기반으로 도메인 지식을 기반으로 만들어진 Rule-based 로직으로 체형을 분석.
  - 체형 분석 결과: 체형 분석 결과를 사용자 및 LLM에게 제공해서 LLM이 더 정확한 운동 및 식단 계획을 생성할 수 있도록 지원.

- **사용자 온보딩 및 계정**
  - **프롤로그 (Tutorial)**: 서비스 첫 진입 시 핵심 플로우와 사용법을 안내하는 튜토리얼 기능.
  - 회원가입 및 인증: 이메일 중복 체크를 포함한 계정 생성 및 안전한 로그아웃.

- **개인화 설정**
  - 상세 프로필 관리: 운동 목표(감량/증량 등), 운동 선호도, 건강 특이사항 설정 및 수정.

- **기록 및 정보 관리**
  - **인바디 히스토리**: 과거에 기록한 모든 인바디 데이터 조회 및 새로운 인바디 기록 추가.
  - 운동 가이드: 각 운동 종목의 올바른 자세를 돕는 학습용 가이드 영상 제공.



## 🚀 핵심 기술 구현 (Technical Focus) - 베타 버전 업데이트 내역

베타 버전에서는 LangGraph 기반의 멀티턴 챗봇 및 휴먼 피드백 루프 등 핵심 기능을 성공적으로 구현함과 동시에, 서비스 안정성과 신뢰성 확보를 위해 아래의 엔지니어링 이슈들을 해결함.

### 🔹 LLM 워크플로우 및 상태 관리 (LangGraph)
- **멀티턴 아키텍처 전환**: 기존 싱글턴 방식에서 LangGraph를 활용한 **상태 기반 멀티턴 챗봇 시스템**으로 개편 완료.
- 세션 및 맥락 유지: `thread_id` 기반의 체크포인트 시스템 도입을 통해 대화 맥락을 유지하고 대화 상태 관리 최적화.
- **휴먼 피드백(Human Feedback) 루프**: 사용자의 피드백을 상태(State)에 반영하여 운동 및 식단 계획을 동적으로 재구성하는 **Refine 루프 구현**.
- 지능형 프롬프트 고도화: 질문 의도 파악 및 상황별 최적화된 답변 제공을 위한 단계별 프롬프트 체계 구축.

### 🔹 백엔드 리팩토링
- **도메인 중심 에러 핸들링**: FastAPI(`HTTPException`) 의존성을 서비스 레이어에서 제거하고 **커스텀 예외 클래스**를 도입하여 독립적인 에러 핸들링 구축.
- **외부 모듈의 서비스화**: 알파 버전에서 `sys.path`를 통해 외부에서 호출하던 체형 분석 로직을 `backend/services/ocr` 내부로 통합하여 패키지 의존성 및 import 구조 최적화.

### 🔹 검증 체계 구축 (Reliability & Testing)
- **테스트 코드 자동화**: 수동 검증 방식에서 **Pytest 기반의 유닛 및 통합 테스트 체계**로 전환하여 로직의 신뢰성 확보.
- 파이프라인 안정성 확보: 변동성이 큰 LLM 응답 및 OCR 데이터 추출 파이프라인에 대한 단계별 통합 테스트 수행으로 시스템 신뢰성 강화.

### 🔹 성능 및 UX 개선
- **토큰 단위 스트리밍(Streaming)**: `AsyncOpenAI SDK`를 LangGraph와 함께 사용하여 스트리밍 응답 구현 완료.
- 예외 상황 UX 최적화: OCR 미인식 이미지나 비정상적인 데이터 입력 시, 서버 에러가 아닌 사용자 가이드 메시지를 실시간으로 반환하도록 예외 처리 로직 강화.


## 기술 스택

- **Backend**: Python 3.11+, FastAPI, PostgreSQL
- **Frontend**: React, Vite
- **AI/LLM**: LangGraph 기반 워크플로우 (초기 구조 구성단계)
- **패키지 관리**: uv (백엔드), npm (프론트엔드)

## 설치 및 실행

### 사전 요구사항

- Python 3.11 이상
- Node.js & npm
- PostgreSQL
- uv (`curl -LsSf https://astral.sh/uv/install.sh | sh`)

### 1. 데이터베이스 설정
```bash
# PostgreSQL 시작
sudo service postgresql start

# 데이터베이스 생성
createdb explainmybody
```

### 2. 백엔드 실행
```bash
cd backend

# 환경변수 설정 (API 키 등)
cp .env.example .env
# .env 파일 열어서 필요한 값 입력
- `DATABASE_URL`: PostgreSQL 접속 주소
- `OPENAI_API_KEY`: LangGraph/LLM 사용을 위한 키
# 의존성 설치
uv sync

# 서버 실행
uv run uvicorn main:app --reload
```

→ 백엔드: http://localhost:8000

**백엔드 실행 상세 가이드**: [backend/BACKEND_QUICKSTART.md](./backend/BACKEND_QUICKSTART.md)

### 3. 프론트엔드 실행
```bash
cd frontend

# 의존성 설치
npm install

# 개발 서버 실행
npm run dev
```

→ 프론트엔드: http://localhost:5173 (기본 Vite 포트)

## 알려진 제약사항 (베타 버전)

- 인증/보안 로직 미완성
  - 로그인 시 비밀번호 검증 미구현
  - 회원가입 시 이메일 중복 체크만 동작
- 대화 세션 관리: 현재 스레드 기반 관리가 도입되었으나, 장기적인 대화 기록의 효율적인 DB 인덱싱 최적화 중
- Human-in-the-loop (HITL) 고도화: 현재 피드백 기반 재작성 로직이 작동 중이나, LangGraph의 interrupt 기능을 활용한 정교한 승인/수정 워크플로우로 전환 예정.
- 사용자 동시 접속에 대한 구조 설계 미완성
